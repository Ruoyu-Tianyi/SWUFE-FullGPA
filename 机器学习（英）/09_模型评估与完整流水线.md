## 1. 先定义正类，再读混淆矩阵

混淆矩阵（Confusion Matrix）比较真实类别与预测类别。下面约定取消订单为正类：`Canceled = 1`，未取消为负类：`Canceled = 0`。

| 实际值 \ 预测值 | 预测 0：未取消 | 预测 1：取消 |
|---|---|---|
| 实际 0：未取消 | 真负例（True Negative, TN） | 假正例（False Positive, FP） |
| 实际 1：取消 | 假负例（False Negative, FN） | 真正例（True Positive, TP） |

`True/False` 表示预测是否正确，`Positive/Negative` 表示预测成了哪一类。

- 假正例（FP）：误报，实际没取消却预测取消；对应第一类错误（Type I Error）。
- 假负例（FN）：漏报，实际取消却预测没取消；对应第二类错误（Type II Error）。

scikit-learn 在 `labels=[0, 1]` 时，行是真实值、列是预测值，排列为：

$$\begin{bmatrix}TN&FP\\FN&TP\end{bmatrix}.$$

课堂部分表格把正类放在第一行和第一列，位置会变成 `[[TP, FN], [FP, TN]]`。**先读标签顺序，不要只背四个格子的位置。**

## 2. 四个核心分类指标

记 $N=TP+TN+FP+FN$。

| 指标 | 公式 | 它回答什么 |
|---|---|---|
| 准确率（Accuracy） | $(TP+TN)/N$ | 全部样本中判对多少 |
| 精确率（Precision, P） | $TP/(TP+FP)$ | 预测为正的里面有多少真是正 |
| 召回率（Recall, R） | $TP/(TP+FN)$ | 实际为正的里面找出了多少 |
| F1 分数（F1 Score） | $2PR/(P+R)=2TP/(2TP+FP+FN)$ | 精确率与召回率的调和平均 |

精确率的分母来自“预测正类”，召回率的分母来自“真实正类”。F1 不是 $(P+R)/2$，也不直接考虑 TN。

分母为 0 时，指标在数学上需要特殊处理。代码可设置 `zero_division=0` 采用明确的返回约定；不要把“没有预测正类”解释为精确率必然等于 1。

类别不平衡（Class Imbalance）时，准确率可能掩盖完全漏掉少数类的问题；应根据业务需求同时检查混淆矩阵、召回率、精确率与成本。

### 手算例题：指标与业务损失

**自建例题，成本采用 Assignment 3。** 某测试集有 100 个订单：

$$\begin{bmatrix}TN&FP\\FN&TP\end{bmatrix}=\begin{bmatrix}65&5\\10&20\end{bmatrix}.$$

因此：

$$Accuracy=\frac{65+20}{100}=0.85,$$

$$P=\frac{20}{20+5}=0.8,\qquad R=\frac{20}{20+10}=\frac23\approx0.667,$$

$$F1=\frac{40}{40+5+10}=\frac8{11}\approx0.727.$$

作业设定：酒店对预测会取消的订单超售；FP 导致客人到店却无房，成本约 400 美元；FN 导致空房，成本约 150 美元。因此：

$$C=400FP+150FN=400\times5+150\times10=3500.$$

若全部预测不取消，30 个实际取消订单全部成为 FN，成本为 $30\times150=4500$。这个模型相对该基线节省 1000 美元。

FP 更贵，因此需要重视精确率，减少错误触发超售。但最终应比较**总成本**；不能只因精确率更高就无条件选模型，因为漏报数量也会变化。

### 最小指标代码

```python
from sklearn.metrics import (
    confusion_matrix, accuracy_score,
    precision_score, recall_score, f1_score,
)

y_true = [0] * 70 + [1] * 30
y_pred = [0] * 65 + [1] * 5 + [0] * 10 + [1] * 20

cm = confusion_matrix(y_true, y_pred, labels=[0, 1])
tn, fp, fn, tp = cm.ravel()
print(cm)
print(accuracy_score(y_true, y_pred))
print(precision_score(y_true, y_pred, zero_division=0))
print(recall_score(y_true, y_pred, zero_division=0))
print(f1_score(y_true, y_pred, zero_division=0))
print(400 * fp + 150 * fn)  # 3500
```

## 3. 留出法：训练、验证、测试各司其职

留出法（Holdout Validation）把有标签数据分成不同部分。

| 数据部分 | 用途 | 可以据此做选择吗 |
|---|---|---|
| 训练集（Training Set） | 拟合模型、填充器、标准化器、编码器 | 可以 |
| 验证集（Validation Set） | 比较特征、模型、参数与阈值 | 可以 |
| 测试集（Test Set） | 选择结束后估计泛化表现 | 不用于后续选择 |

课程练习使用 60% / 20% / 20%。先取出总样本的 20% 作为测试集，再从剩余的 80% 中取出四分之一，得到总样本的 20% 作为验证集。

```python
# 假设 X、y 已准备好，且每个类别有足够样本
from sklearn.model_selection import train_test_split

# X_dev, X_test, y_dev, y_test = train_test_split(
#     X, y, test_size=0.2, random_state=409
# )
# X_train, X_val, y_train, y_val = train_test_split(
#     X_dev, y_dev, test_size=0.25, random_state=409
# )
```

这里保留课堂指定的随机划分方式；为了与作业的 2,709 个测试订单一致，不应自行添加 `stratify` 或提前删行。其他分类项目可考虑 `stratify=y` 保持类别比例，但那是另一种划分。

只看一次测试集的意义是：特征、预处理、参数和阈值都已固定。若根据测试结果修改模型，该数据实际上已参与选择，不能再把它当作完全独立的最终检验。

`random_state` 使随机划分可复现，不会让某个划分天然更可靠，也不应不断换种子直到分数最高。

补充理解：有时间先后关系或同一客户多行的数据，随机按行切分可能使信息跨集合流动，应根据预测场景考虑按时间或实体划分。此处用于理解泄漏，不扩展为新的考试章节。

## 4. 过拟合与欠拟合

| 状态 | 训练表现 | 验证表现 | 常见处理思路 |
|---|---|---|---|
| 欠拟合（Underfitting） | 较差 | 较差 | 更合适的特征、更有表达力的模型、减弱过强限制 |
| 过拟合（Overfitting） | 很好 | 明显较差 | 剪枝、减少不必要特征、更多有代表性的数据 |
| 泛化较好 | 较好 | 与训练表现接近且较好 | 继续检查稳定性与业务成本 |

这些是诊断线索，不是仅靠两行数字就能绝对判定的定理。训练和验证分数都低，也可能来自目标噪声、错误标签或不合适的指标。

交叉验证（Cross-Validation）帮助发现问题和选择参数；它本身不会把同一棵过深的树自动变简单。更多样本也不能保证修复一个表达能力不足的模型。

## 5. K 折交叉验证如何工作

先保留最终测试集。把剩余的开发数据（Development Data）划成 $K$ 折：每轮用 $K-1$ 折训练，剩下一折验证，轮流做 $K$ 次，得到 $K$ 个验证分数。

$$\overline{s}_{CV}=\frac1K\sum_{k=1}^{K}s_k.$$

一次 5 折交叉验证中，每个样本作为验证样本一次，作为训练样本四次；每个模型只看到开发数据的约 80%。最终选定参数后，要用**全部开发数据重新拟合（Refit）**，而不是随便取其中一折的模型作为最终模型。

`cross_validate(..., scoring="accuracy")` 返回 `test_score`；若使用多指标列表，例如 `scoring=["accuracy", "f1"]`，则返回 `test_accuracy`、`test_f1`。这里的 `test` 指交叉验证的留出折，**不是锁定的最终测试集**。

设置 `return_train_score=True` 可获得每折训练分数，用于对比训练与验证差距。预处理器必须与模型一起放入流水线，让每折独立学习其训练部分的统计量。

## 6. 网格搜索：组合数、拟合次数、最优结果

网格搜索（Grid Search）穷举预先指定的超参数（Hyperparameters）组合，再用交叉验证比较。

例如 `criterion` 有 2 种、`max_depth` 有 5 种：

$$\text{组合数}=2\times5=10.$$

每组做 5 折交叉验证，需要 $10\times5=50$ 次拟合。在默认 `refit=True` 且正常完成时，最佳组合还会在全部传入训练数据上拟合一次：

$$\text{总拟合次数}=\text{组合数}\times K+1=51.$$

课堂完整流水线的网格是：填充策略 2 种 × 准则 2 种 × 深度 5 种 × 分类填充策略 1 种，配合 10 折交叉验证，总计 $20\times10+1=201$ 次树拟合。若 `refit=False`，没有最后的 $+1$。

这里数的是模型拟合次数，不是不同超参数组合数；每次拟合还会学习对应流水线中的预处理参数。

| 属性 | 应如何理解 |
|---|---|
| `best_params_` | 最优超参数组合 |
| `best_score_` | 最优组合的平均交叉验证分数 |
| `cv_results_["mean_test_score"]` | 每个候选组合各自的平均验证分数 |
| `best_estimator_` | 默认重新拟合后可直接预测的最佳模型/流水线 |

不要把所有候选组合的 `mean_test_score` 再取平均，当成最佳模型分数。课程有展示这个总体均值，但它与 `best_score_` 回答的是不同问题。[GridSearchCV 官方定义](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GridSearchCV.html)

参数路径使用**双下划线**：`preprocessor__num_pipeline__imputer__strategy`，表示依次进入预处理器、数值分支、填充器，再设置其 `strategy`。实际路径必须与自己定义的步骤名一致。

## 7. 可运行的完整流水线

下例用自建的 60 行教学数据演示结构，不需要下载数据；其分数不代表 Titanic 或 Lakeside 的真实表现。正类仍为 1，但这里目标名为示意的 `target`。

```python
import numpy as np
import pandas as pd
from sklearn.model_selection import (
    train_test_split, StratifiedKFold, GridSearchCV,
)
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score, confusion_matrix

# 自建数据，先生成完整特征与标签
rng = np.random.default_rng(409)
n = 60
age = rng.integers(18, 70, size=n).astype(float)
fare = rng.uniform(10, 100, size=n)
sex = rng.choice(["female", "male"], size=n).astype(object)
target = (((sex == "female") & (age < 50)) | (fare > 70)).astype(int)
age[::11] = np.nan
sex[::13] = np.nan
X = pd.DataFrame({"Age": age, "Fare": fare, "Sex": sex})
y = pd.Series(target, name="target")

# 本示例使用分层划分，不复现作业指定测试集
X_dev, X_test, y_dev, y_test = train_test_split(
    X, y, test_size=0.2, random_state=409, stratify=y
)
num_features = ["Age", "Fare"]
cat_features = ["Sex"]

num_pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
])
cat_pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore")),
])
preprocessor = ColumnTransformer([
    ("num_pipeline", num_pipeline, num_features),
    ("cat_pipeline", cat_pipeline, cat_features),
])
pipeline = Pipeline([
    ("preprocessor", preprocessor),
    ("tree", DecisionTreeClassifier(random_state=409)),
])

param_grid = {
    "preprocessor__num_pipeline__imputer__strategy": ["mean", "median"],
    "tree__criterion": ["gini", "entropy"],
    "tree__max_depth": [1, 2, 3, 4, 5],
}
cv = StratifiedKFold(n_splits=3, shuffle=True, random_state=409)
search = GridSearchCV(pipeline, param_grid, cv=cv, scoring="accuracy")
search.fit(X_dev, y_dev)

# 20 个组合 × 3 折 + 1 次重拟合 = 61 次
best = search.best_estimator_
print(search.best_params_)
print(search.best_score_)

# 选择完成后再评估测试集
prediction = best.predict(X_test)
print(accuracy_score(y_test, prediction))
print(confusion_matrix(y_test, prediction, labels=[0, 1]))
```

这段代码值得逐层解释：

1. `ColumnTransformer` 按列把数值特征和类别特征送入不同分支，再拼接输出。
2. `Pipeline` 按顺序执行各步骤，最后一步是模型。
3. 搜索的每个训练折都重新拟合填充器、标准化器、编码器和树。
4. `best.predict(X_test)` 自动执行已经学好的预处理，再预测；不用手动重复填充与编码。
5. 分类填充器明确设为 `most_frequent`，所以即使不运行网格搜索也能处理字符串。

原课件的分类分支先写 `SimpleImputer()`，后来通过网格设成 `most_frequent`；如果只复制前半段直接 `fit`，默认 `mean` 会导致字符串填充失败。这里把可用策略直接写入分支。

## 8. 特征重要性：模型为什么这样预测

基于不纯度下降的重要性（Mean Decrease in Impurity, MDI）统计某个特征在树中所有切分带来的加权不纯度下降。

设训练集总样本数为 $N$，内部节点 $t$ 有 $n_t$ 个样本，左右孩子分别为 $n_L,n_R$；节点贡献为：

$$\Delta_t=\frac{n_t}{N}\left[I_t-\frac{n_L}{n_t}I_L-\frac{n_R}{n_t}I_R\right].$$

某个特征 $j$ 的原始贡献为所有使用它的节点贡献之和，再除以所有特征的总贡献得到重要性：

$$FI_j=\frac{\sum_{t:\,split(t)=j}\Delta_t}{\sum_t\Delta_t}.$$

存在有效分裂时，通常归一化为总和 1；若树完全没有分裂，重要性可以全为 0。上式为无样本权重情形；带权训练使用相应加权计数。

**自建手算。** 特征 A 在根节点贡献 0.20，又在一个子节点贡献 0.05；特征 B 贡献 0.15。总贡献 0.40，所以 $FI_A=0.25/0.40=0.625$，$FI_B=0.375$。同一特征的贡献必须跨节点相加；根节点使用的特征不保证在所有树中都是最终最重要的。

### 编码后列数为什么更多

原始 3 个特征可能被变为 4 列：`Age`、`Fare`、`Sex_female`、`Sex_male`。重要性数组对应**模型实际输入的编码后列**，应按相同顺序取列名。

以下续接上一节的完整代码：

```python
prep = best.named_steps["preprocessor"]
tree = best.named_steps["tree"]
names = prep.get_feature_names_out()

importance = pd.Series(tree.feature_importances_, index=names)
print(importance.sort_values(ascending=False))

# 将独热列按原始特征汇总
encoder = prep.named_transformers_["cat_pipeline"].named_steps["onehot"]
origins = num_features + [
    feature
    for feature, categories in zip(cat_features, encoder.categories_)
    for _ in categories
]
by_original = pd.Series(tree.feature_importances_).groupby(origins).sum()
print(by_original.sort_values(ascending=False))
```

这里汇总代码适用于上例的“不丢弃类别、不合并低频类别、无全缺失列”设置。若变更编码策略，需要同步更新映射。不要简单取列名第一个下划线前的字符串：`lead_time` 这种原始名称本身就有下划线。

### 重要性不能说明什么

- 没有方向：0.6 的重要性不代表该特征越大，正类概率就越高。
- 不是因果效应（Causal Effect）：能预测取消的变量，不一定是取消的原因。
- 不是个体解释：总体重要性不等于某一个订单的具体决策原因。
- 零重要性不等于无用：另一相关特征可能已承担同样的信息，或树太浅没有使用它。
- 不是无偏的通用排名：不纯度重要性可能偏向可切分取值多的特征，且相关特征会分担或替代贡献。

比较分组结果可辅助理解方向，但更细的条件关系应直接读树的分支，不能只用总体分组比例替代模型解释。发现预测时不可能获得的变量异常重要，例如“退款已发生”，还应排查泄漏。

## 9. 置换重要性：与后续回归内容衔接

置换重要性（Permutation Importance）固定已训练模型，将某一输入列的值随机打乱，观察分数下降：

$$PI_j=\text{原始分数}-\text{打乱特征 }j\text{ 后的分数}.$$

它不需要重新训练模型，可用于多种模型。若使用 `neg_root_mean_squared_error`，分数下降对应 RMSE 增加。重要性接近 0 或小于 0 可能来自该特征贡献有限、噪声或样本波动；高度相关的特征可能互相替代，使各自的重要性偏低。[置换重要性官方说明](https://scikit-learn.org/stable/modules/permutation_importance.html)

以下代码续接已固定的 `best`，在测试集上只作最终报告解释；不能再据此筛特征、调模型后仍称该测试集完全独立。

```python
from sklearn.inspection import permutation_importance

result = permutation_importance(
    best, X_test, y_test,
    scoring="accuracy", n_repeats=5, random_state=409,
)
print(pd.Series(result.importances_mean, index=X_test.columns))
```

因为传入的是完整流水线与原始 DataFrame，这里直接得到原始列层面的重要性。若重要性用于选择特征，应在训练/验证流程内进行，最终测试数据继续保留。

## 10. 阈值、PR 与 ROC/AUC：课件标为可选

本节在课程页面标题中标为可选（Optional），考试页未单独声明排除。先掌握核心指标和评估流程，再复习本节定义与方向。

对模型返回的正类分数 $s(x)$，可以规定阈值 $t$：$s(x)\geq t$ 时预测正类。概率列的顺序应查 `classes_`，不能对所有模型都假定第二列一定对应想要的正类。

提高阈值会使预测正类集合缩小，因此在同一组固定分数上，召回率不会上升；精确率通常会上升，但**不保证单调上升**。某一步若删除了较多真正例，精确率也可能下降。平票处理及默认预测规则可能依模型而异。

精确率—召回率曲线（Precision-Recall Curve, PR Curve）通常以召回率为横轴、精确率为纵轴，描述阈值变化下的表现。平均精确率（Average Precision, AP）可用作曲线的汇总指标；不必把它与所有实现中的几何面积完全等同。

受试者工作特征曲线（Receiver Operating Characteristic Curve, ROC Curve）：

$$TPR=\frac{TP}{TP+FN}=Recall,\qquad FPR=\frac{FP}{FP+TN}.$$

横轴是假正率（False Positive Rate, FPR），纵轴是真正率（True Positive Rate, TPR）。越靠近左上角通常越好。

曲线下面积（Area Under the ROC Curve, AUC）概括不同阈值下的排序能力：随机排序的期望约 0.5；完美排序为 1；也可能小于 0.5。更精确的概率解释是：随机选一正一负样本，正样本得分更高的概率，加上平分概率的一半。

计算 AUC 应使用概率或连续决策分数，而不是只传入最终 0/1 预测。AUC 高不保证当前阈值下成本低，也不直接保证概率校准准确。正类稀少时，应同时看 PR 曲线和业务指标，不能把 ROC/AUC 当作自动解决不平衡问题的办法。

```python
# 续接上文 best；本例 classes_ 为 [0, 1]
from sklearn.metrics import roc_auc_score, precision_recall_curve

positive_column = list(best.classes_).index(1)
scores = best.predict_proba(X_test)[:, positive_column]
print(roc_auc_score(y_test, scores))
precision, recall, thresholds = precision_recall_curve(y_test, scores)
```

`precision`、`recall` 比 `thresholds` 多一个元素；画“阈值—指标”图时通常使用 `precision[:-1]` 与 `recall[:-1]` 配对阈值。

## 11. 纸笔自测

1. 有 `confusion_matrix(..., labels=[0,1]) = [[40,10],[5,45]]`，求准确率、精确率、召回率、F1。
2. 某网格含 3 个深度、2 个准则、2 个填充策略，做 5 折交叉验证且默认重新拟合，共拟合多少棵树？
3. 为什么 `cv_results_["mean_test_score"].mean()` 不是最佳模型的交叉验证分数？`test_score` 是否表示最终测试集分数？
4. 先用全体数据拟合标准化器，再对模型做交叉验证，有何问题？
5. 某特征重要性为 0，能否立刻断定应删除？提高分类阈值能否保证精确率升高？

### 自测答案

1. $Accuracy=85/100=0.85$；$P=45/55\approx0.818$；$R=45/50=0.9$；$F1=90/105\approx0.857$。
2. 组合数 $3\times2\times2=12$；总拟合次数 $12\times5+1=61$。
3. 它平均了所有候选组合；最佳组合对应 `best_score_`。CV 的 `test_score` 是验证折分数。
4. 验证折数据已参与均值和标准差估计，形成泄漏；应把预处理放进每折的流水线。
5. 均不能。重要性依赖当前模型和其他特征，应通过训练/验证流程检查删列效果；阈值升高时精确率可能局部下降。
