本章目标：先判断形状（Shape），再判断数值；能把每个轴（Axis）和聚合结果翻译成业务含义。课程咖啡店练习使用 `sales.shape == (3,4,5)`，依次代表门店、周、产品。

## 1. 数组结构与创建

多维数组（N-dimensional Array, `ndarray`）使用统一的数据类型描述元素，支持向量化（Vectorization）运算。数值分析中通常使用数值 `dtype`，不要把 Python 列表与数组的运算规则混为一谈。

| 属性/操作 | 含义 | `a.shape == (2,3,4)` 时 |
|---|---|---|
| `a.ndim` | 轴的个数 | `3` |
| `a.shape` | 每个轴的长度 | `(2,3,4)` |
| `a.size` | 元素总数 | `2*3*4=24` |
| `a.dtype` | 元素的数据类型 | 如 `int64`、`float64` |
| `a.reshape(6,4)` | 在元素数不变时改变形状 | 仍为 24 个元素 |

```python
import numpy as np

a = np.array([[1, 2, 3], [4, 5, 6]])
print(a.shape, a.ndim, a.size)    # (2, 3) 2 6
zeros = np.zeros((2, 3))         # 全零数组
ones = np.ones((2, 3))           # 全一数组
steps = np.arange(1, 6, 2)       # [1, 3, 5]，不含终点
points = np.linspace(0, 1, 3)    # [0., 0.5, 1.]，默认含终点
flat = a.reshape(-1)            # 自动推算唯一未知维度
```

文件中的数值可用 `np.loadtxt("numbers.txt", delimiter=",")` 读取，再按已知结构 `reshape`。不能把 24 个元素直接重塑成 `(5,5)`。

`(5,)` 是一维数组，既不是 `(1,5)` 行矩阵，也不是 `(5,1)` 列矩阵。`a.T` 交换二维数组的行列；一维数组转置后仍是一维，要得到列矩阵需 `a.reshape(-1,1)`。

## 2. 索引：一个整数会消去一个轴

### 2.1 先把三维数组理解成三张门店报表

你管理一家咖啡连锁店，记录了 **3 家门店、4 周、5 种产品**的销量。一个数字表示“某家店在某一周卖出某种产品的数量”，单位为件/杯，不是金额。下面沿用课程数据，后文的 `sales`、`stores`、`products` 均来自这里。

```python
import numpy as np

np.random.seed(409)  # 复现课堂销量
sales = np.random.randint(20, 80, size=(3, 4, 5))
stores = ["Downtown", "Campus", "Airport"]
products = ["Latte", "Espresso", "Cold Brew", "Sandwich", "Cookie"]
```

| 轴 | 代表什么 | 索引与现实对象的对应关系 |
|---|---|---|
| 轴 0，长度 3 | 门店 | 0=市中心店 Downtown；1=校园店 Campus；2=机场店 Airport |
| 轴 1，长度 4 | 周 | 0=第 1 周，1=第 2 周，2=第 3 周，3=第 4 周 |
| 轴 2，长度 5 | 产品 | 0=拿铁，1=浓缩咖啡，2=冷萃，3=三明治，4=曲奇 |

可以把整个数组想成三张叠起来的表：**先选哪家店的一张表，再选表中哪一周的行，最后选哪种产品的列**。NumPy 只保存数字和位置；这些门店名、产品名是我们另行记录的对应关系。

数组用逗号区分不同轴，写作 `sales[门店选择, 周选择, 产品选择]`。`:` 表示该轴全部保留。整数固定一个位置，结果不再需要用那个轴区分不同对象；切片保留一段位置，也保留该轴。**“消去轴”不是删除原数组的数据，而是返回结果少了一个维度。**

### 2.2 从业务问题逐个翻译成索引

**问题 A：校园店长要看自己店四周的完整报表。** 门店固定为 1，周和产品全部保留：

```python
campus = sales[1, :, :]  # 等价于 sales[1]
print(campus.shape)     # (4, 5)：周 × 产品
print(campus)
```

输出如下，4 行分别是第 1–4 周，5 列仍按 `products` 排列：

```text
[[21 59 61 76 61]
 [30 36 58 38 66]
 [36 62 56 47 30]
 [50 28 59 47 64]]
```

例如第一行第三个数 61 是校园店第 1 周的冷萃销量。此时只剩“周”和“产品”两个维度，不再需要门店轴。省略末尾的轴选择时，它们默认全部保留，因此 `sales[1]` 也得到同样的表。

**问题 B：校园店的冷萃每周分别卖出多少杯？** 固定门店 1、产品 2，只让周变化：

```python
campus_cold_brew = sales[1, :, 2]
print(campus_cold_brew)        # [61 58 56 59]
print(campus_cold_brew.shape)  # (4,)
print(campus_cold_brew.sum())  # 234，全月冷萃销量
```

`1` 选校园店，`:` 选四周，`2` 选冷萃。输出的四个数是四周的销量，可以接着画周趋势；若问题改成“全月共多少杯”，才再调用 `.sum()`。**索引负责取出记录，求和负责汇总记录。**

**问题 C：机场店第 2–3 周，两种食品分别卖了多少？** `1:3` 取周索引 1、2，`-2:` 取末尾两种产品：

```python
airport_food = sales[2, 1:3, -2:]
print(airport_food.shape)  # (2, 2)：两周 × 两种食品
print(airport_food)
```

结果为 `[[52,47],[34,56]]`：第 1 行对应第 2 周，第 2 行对应第 3 周；第 1 列是 Sandwich，第 2 列是 Cookie。也就是第 2 周卖了 52 个三明治、47 块曲奇，第 3 周分别为 34、56。虽然两个轴长度都为 2，它们的含义完全不同；仅看 `(2,2)` 并不能知道行列代表什么。

**问题 D：市中心店第 4 周卖了多少杯冷萃？** 三个位置都固定，结果是一个数字：

```python
units = sales[0, 3, 2]
print(units)  # 40 杯
```

### 2.3 对照速查：先说需求，再判断剩下哪些轴

| 选择 | 结果形状 | 业务含义 |
|---|---|---|
| `sales[1]` | `(4,5)` | 校园店完整报表；行是周，列是产品 |
| `sales[:,1]` | `(3,5)` | 三店第 2 周报表；行是门店，列是产品 |
| `sales[1,:,2]` | `(4,)` | 校园店冷萃的四周销量 |
| `sales[:,1:2,:]` | `(3,1,5)` | 第 2 周，保留周这个轴 |
| `sales[2,1:3,-2:]` | `(2,2)` | 第 3 家门店，第 2–3 周，最后两种产品 |
| `sales[0,3,2]` | 标量 | 第 1 家门店，第 4 周，第 3 种产品 |

### 2.4 为什么有时只取一周，也要保留周轴？

`sales[:,1,:]` 和 `sales[:,1:2,:]` 都取第 2 周的数据，但前者为 `(3,5)`，后者为 `(3,1,5)`。后续函数若要求统一接收“门店 × 周 × 产品”，应使用后者。这样同一函数既可处理一周，也可处理多周。

```python
one_week_table = sales[:, 1, :]     # 门店 × 产品
one_week_block = sales[:, 1:2, :]   # 门店 × 周 × 产品
print(one_week_table.shape)        # (3, 5)
print(one_week_block.shape)        # (3, 1, 5)
```

切片包含起点、不包含终点；“第 2 周”对应索引 1，不是 2。对结果继续索引时，要按**结果的新轴顺序**理解：`campus[0,2]` 是校园店第 1 周的冷萃销量，已不再需要传入门店索引。

### 2.5 布尔索引：哪些周需要重点关注？

接问题 B，假设店长想找出“冷萃销量少于 60 杯的周”，用于进一步排查活动、客流或营业天数：

```python
week_numbers = np.arange(1, 5)  # 现实周次 1–4
low = campus_cold_brew < 60
print(low)                    # [False True True True]
print(week_numbers[low])       # [2 3 4]：对应周次
print(campus_cold_brew[low])    # [58 56 59]：对应销量
```

布尔掩码（Boolean Mask）中的每个 `True` 保留相同位置的元素。只输出 `[58,56,59]` 会丢掉“是哪几周”的说明，因此同时筛选周次。阈值 60 是本例的业务筛选条件，不是统计异常值的通用界限。

## 3. 逐元素运算、复制与矩阵运算

```python
a = np.array([1, 2, 3])
b = np.array([4, 5, 6])
print(a + b)         # [5, 7, 9]
print(a * b)         # [4, 10, 18]
print(a ** 2)        # [1, 4, 9]
print(a @ b)         # 32：1*4 + 2*5 + 3*6
```

逐元素（Element-wise）运算按位置进行；`*` 不是矩阵乘法，`@` 才表示矩阵乘法/向量点积。二维矩阵 `(m,k) @ (k,n)` 得到 `(m,n)`，中间维度必须相同。这也是后续线性回归矩阵公式的基础。

NumPy 的**基本切片通常是视图（View）**，修改它会影响原数组；要独立数据应 `.copy()`。布尔索引、整数数组索引通常生成复制，不能把所有索引结果都当成视图。

```python
a = np.array([1, 2, 3, 4])
b = a[1:3]             # 共享原数组数据
b[0] = 99
print(a)               # [1, 99, 3, 4]
c = a[1:3].copy()      # 独立复制
c[0] = 0
print(a)               # 仍为 [1, 99, 3, 4]
```

## 4. 聚合：`axis` 指定“被合并掉的维度”

聚合（Aggregation）包括 `sum`、`mean`、`min`、`max`、`std` 等。`a.sum()` 默认汇总所有元素，**不指定 `axis` 并不等于默认按 `axis=0` 汇总**。

对于二维数组：`axis=0` 合并各行，保留每列一个结果；`axis=1` 合并各列，保留每行一个结果。“沿哪个方向”容易记错，直接检查被删除的形状位置更稳妥。

```python
a = np.array([[1, 2, 3], [4, 5, 6]])
print(a.sum())                    # 21
print(a.sum(axis=0))              # [5, 7, 9]，形状 (3,)
print(a.sum(axis=1))              # [6, 15]，形状 (2,)
print(a.mean(axis=0))             # [2.5, 3.5, 4.5]
print(a.sum(axis=1, keepdims=True))  # [[6], [15]]，形状 (2, 1)
```

三维咖啡店案例：

| 表达式 | 结果形状 | 一个结果元素表示什么 |
|---|---|---|
| `sales.sum(axis=0)` | `(4,5)` | 某周某产品，所有门店合计 |
| `sales.sum(axis=1)` | `(3,5)` | 某门店某产品，全月合计 |
| `sales.sum(axis=2)` | `(3,4)` | 某门店某周，所有产品合计 |
| `sales.sum(axis=(1,2))` | `(3,)` | 每家门店全月总销量 |
| `sales.sum(axis=(0,1))` | `(5,)` | 每种产品全月总销量 |
| `sales.sum(axis=(0,2))` | `(4,)` | 每周所有门店、产品总销量 |

`keepdims=True` 将被汇总的轴保留为长度 1，常用于后续广播。`np.median(a)` 求中位数；`np.std(a)` 默认用总体标准差口径，即 `ddof=0`，与 Pandas `.std()` 默认口径不同。

### 把汇总结果读成一张新报表

**需求：查看每家店全月各产品销量，比较产品构成。** 每家店与每种产品仍要分别显示，只有“周”要合并，所以对原数组的轴 1 求和：

```python
month_by_store_product = sales.sum(axis=1)
print(month_by_store_product.shape)  # (3, 5)：门店 × 产品
print(month_by_store_product[1, 2])  # 234：校园店全月冷萃

store_total = month_by_store_product.sum(axis=1, keepdims=True)
product_share = month_by_store_product / store_total
print(store_total.shape)            # (3, 1)：每店一个总销量
print(round(product_share[1, 2], 4)) # 0.2376：校园店冷萃占比
```

第一步的 `axis=1` 是原数组的周轴；第二步的 `axis=1` 是**新二维报表的产品轴**。轴号取决于当前对象，不会永久绑定“周”。`store_total` 保留为 `(3,1)`，能让每店的五种产品分别除以自己店的总量。例如校园店冷萃占比是 `234/985`，不是除以三店合计销量。

如果只关心“第 2 周三家店各卖了多少”，先筛出这一周，再把产品合计：

```python
week2 = sales[:, 1, :]          # (3, 5)：门店 × 产品
week2_units = week2.sum(axis=1) # 合计每家店的五种产品
print(week2_units)             # [215 228 243]
```

结果依次对应 Downtown、Campus、Airport。这里先索引再聚合；若先把四周全部相加，就不能再回答单独第 2 周的问题。

## 5. 最大值与最大值位置

`max()` 返回数值，`argmax()` 返回最大值的位置；`argmin()` 同理。默认 `argmax()` 将整个数组按顺序展开后返回位置，指定 `axis` 则返回该轴上的位置；并列时返回首先出现的位置。

```python
a = np.array([[8, 2, 6], [3, 9, 1]])
print(a.max())              # 9
print(a.argmax())           # 4：展开后的索引
print(a.argmax(axis=0))     # [0, 1, 0]：每列最大值所在行
print(a.argmax(axis=1))     # [0, 1]：每行最大值所在列
```

**需求：向老板报告“哪种产品销量最高、卖了多少”。** 分成“汇总销量→找位置→取名字”三步，更容易检查：

```python
product_units = sales.sum(axis=(0, 1))  # 各产品跨门店、周合计
best_index = product_units.argmax()
print(best_index)                      # 4，是位置，不是销量
print(products[best_index], product_units[best_index])  # Cookie 623
```

压缩写法 `products[sales.sum(axis=(0,1)).argmax()]` 只返回名称。`products` 顺序必须与产品轴一致，否则数字算对也会贴错产品标签。

## 6. 广播（Broadcasting）：从右向左比较

两数组逐元素运算时，从最右边的维度开始对齐。对应长度**相等，或至少一个为 1**，才可兼容；缺失的左侧维度视作 1。

```text
sales: (3, 4, 5)
price:       (5,)  → (1, 1, 5) → 可广播，结果 (3, 4, 5)
cost:        (3,)  → (1, 1, 3) → 末轴 5 与 3 不兼容
cost.reshape(3,1,1)           → 每门店一个系数，兼容
```

数组广播不是“看到相同数字就自动找到对应轴”。`price` 对齐末轴产品维度；门店系数必须显式放在门店轴上。

```python
np.random.seed(409)
sales = np.random.randint(20, 80, size=(3, 4, 5))
price = np.array([3.5, 3.0, 4.5, 6.5, 2.0])
cost = np.array([1.0, 1.2, 0.9])

revenue = sales * price                 # 数量 × 对应产品单价
store_units = sales.sum(axis=(1, 2))    # [934, 985, 1012]
store_revenue = revenue.sum(axis=(1, 2)) # [3628., 3881.5, 3902.5]
adjusted = sales * cost.reshape(3, 1, 1)
```

**把广播展开成一个具体位置的计算：** `revenue[0,3,2] = sales[0,3,2] * price[2] = 40 * 4.5 = 180`，表示市中心店第 4 周冷萃收入 180 美元。五个单价沿产品轴对应，自动用于所有门店、所有周；不是把总收入乘五次。

若只做“校园店销量统一放大 20%”的情景演示，则 `cost[1]=1.2` 应作用于 `sales[1,:,:]` 里的每一个数。`reshape(3,1,1)` 中的 3 对准门店，两个 1 允许系数沿周与产品重复使用。例如校园店第 1 周冷萃为 `61*1.2=73.2` 个等效单位，这是调整后的情景量，不是实际发生了小数杯销量。

本例 `cost` 是课程给定的门店系数练习。`adjusted` 的业务含义由系数定义决定，不能仅凭变量名就称其为利润；利润还需要成本金额等信息。

销量最高不等于收入最高，收入最高也不等于利润最高。课堂数据中 Cookie 销量最高、Sandwich 收入最高，说明选择指标前必须明确问题。

## 7. 纸笔例题与解答

**题目。** `x=np.array([[2,4,6],[1,3,5]])`，`p=np.array([10,20,30])`。求 `(x*p).sum(axis=1)`，并写出中间和最终形状。

**解答。** `x` 为 `(2,3)`，`p` 的 `(3,)` 对齐最后一轴，乘积为 `[[20,80,180],[10,60,150]]`，形状 `(2,3)`。沿 `axis=1` 合并产品轴，得到 `[280,220]`，形状 `(2,)`。若行代表门店，这就是每店收入。

## 8. 易错点与自测

常见错误：把 `size` 当行数；把 `(n,)` 当列矩阵；把 `axis=0` 当“保留轴 0”；把最大值位置当最大值；基本切片修改后忘记原数组同步变化；广播时从左对齐。

1. `(3,4,5)` 有几个轴、多少元素？
2. `sales[:,1:2,2]` 的形状是什么？
3. `sales.mean(axis=(0,2), keepdims=True)` 的形状是什么？
4. `(4,1)` 与 `(3,)` 相加结果形状是什么？
5. 要计算每周收入，怎样从 `revenue` 汇总？

**简答：** 1. 3 个轴、60 个元素。2. `(3,1)`。3. `(1,4,1)`。4. `(4,3)`。5. `revenue.sum(axis=(0,2))`，形状 `(4,)`。
